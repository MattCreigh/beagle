Exclusion that dominates the census

The repository tracks 3,879 TypeScript and JavaScript files — every one of them under src/beagle/frontends/pi/vendor/, being a vendored pi prebuild plus its committed node_modules. Scale factors rated

Five factors set the exponent, and the exponent decides whether the project shows economies or diseconomies of scale. Each rating below is a judgment, justified against something checkable in the repository.

Scale factors — COCOMO II.2000 values
FactorRatingValueBasis
PREC precedentedness Low4.96 Agentic workflow engine with RAG, graph traversal, MCP servers, sandboxed execution and a coordination store. Largely unprecedented product class.
FLEX development flexibility High2.03 No external client contract. Constrained instead by a self-imposed doctrine enforced in CI (beagle-doctrine-gates.yml), which is a real conformance cost.
RESL risk / architecture resolution High2.83 docs/ADR.md, docs/decisions/, docs/spec/, threat-model.md and a security whitepaper — architecture and risk are resolved in writing before code.
TEAM team cohesion Very High1.10 Single author across all 77 commits. No stakeholder negotiation cost of any kind.
PMAT process maturity High3.12 Seven CI workflows (test, security audit, SBOM, doctrine gates, version check, Docker, licence), pre-commit hooks, a strict mypy ratchet, and a project-wide QA gate in qup.toml.
Σ SF14.04→ E = 0.91 + 0.01 × 14.04 = 1.0504

An exponent above 1.0 means diseconomy of scale — each additional thousand lines costs slightly more than the last. At 1.0504 the penalty is mild: doubling the codebase would cost 2.07× rather than 2×. The unprecedented problem domain is what keeps it above one; the mature process and single-author cohesion are what keep it from going higher.

The calculation

Both equations worked with the values above, for the production-source input.

E= 0.91 + 0.01 × ΣSF = 0.91 + 0.01 × 14.04 = 1.0504
PM= 2.94 × SizeE × ΠEM = 2.94 × 65.2021.0504 × 0.3823 = 90.5 person-months
F= 0.28 + 0.2 × (E − 0.91) = 0.3081
TDEV= 3.67 × PMF = 3.67 × 90.50.3081 = 14.7 calendar months
Staff= PM ÷ TDEV = 90.5 ÷ 14.7 = 6.2 average FTE

07

What actually happened

The model's output against the repository's own record — and where the model breaks.

A caveat on dating the project

Git history cannot date this work. The first commit is 2026-08-24 · "initial tracked state — beagle v1.3.0" — history was squashed at v1.3.0, so all 77 commits fall inside four days. The CHANGELOG.md is the only surviving timeline: 24 releases with dated entries running 2025-03-28 → 2026-08-28, about 17 months. That is the figure used below, and it is softer evidence than the SLOC census.

  • Schedule: the model is close. Predicted 14.7 calendar months against roughly 17 actual. For an uncalibrated estimate that is well inside the model's own error band — COCOMO's schedule equation is the part that survives here.
  • Staffing: the model is wrong by 6×. It predicts 6.2 average FTE. The repository shows one author on every commit. The work got done in about the predicted time with roughly one-sixth of the predicted people.
  • Implied productivity. The model expects 720 SLOC per person-month. The actual rate is about 3,835 — 5.3× the model's expectation on production source, and 8.9× if test code is counted as delivered.
  • Where that factor comes from. COCOMO II has no term for it. Its most favourable productivity lever, ACAP and PCAP at Very High, caps out at a combined 0.54× — it cannot express a 5× effect, because in 2000 no such effect existed to calibrate against. The model's residual is the measurement.
  • What the residual is not. It is not free. The 8,786 lines of documentation, seven CI gates, strict typing and 3,368 tests are precisely the scaffolding that makes a productivity rate like this survivable, and the model charges for all of it — DOCU and RELY together add 35% to the estimate. Removing that scaffolding would cut the modelled cost and destroy the actual result.
Bottom line

Beagle's production source represents roughly 7.5 person-years and $1.1M–$1.8M of conventionally-organised engineering, delivered on approximately the schedule COCOMO II predicts, by about one-sixth of the staff it predicts. Use the cost figure for insurance, valuation or replacement-planning arguments. Do not use the staffing figure to plan anything — the model has no vocabulary for how this was built.
