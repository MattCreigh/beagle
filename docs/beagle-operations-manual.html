1Front Matter

1.1Purpose and Scope

This document specifies the architecture, interfaces, security posture, and operational procedures of Beagle, version 1.4.1. It is derived by direct analysis of the source distribution and is intended for solutions architects evaluating the system, platform engineers deploying it, and site reliability engineers operating it.

Scope covers the open-source engine as distributed. It excludes the separately licensed beagle-orpheus shared-memory transport, which is an optional, operator-installed plugin and is not a dependency of any code path described here.

1.2Executive Summary

Autonomous LLM agents fail in three commercially significant ways: they consume unbounded API spend, they act outside their intended blast radius, and they return confident output that is not true. Beagle is an execution substrate that constrains all three as a precondition of running work at all.

A request enters as a natural-language query bound to a named workflow and a hard USD ceiling. Beagle compiles it into a directed acyclic graph of agent phases, hydrates each phase with real code context retrieved from a hybrid vector-plus-graph index of the target repository, executes each phase as an isolated sub-agent process, and subjects the result to an adversarial cross-verification pass before releasing it. Every model call is metered against the ceiling; every run is recorded to a relational store with a per-node cost breakdown, so an operator can answer "what did this cost and which agent spent it" after the fact.

The commercial argument is governance. The engine converts agentic work from an open-ended spend with unverified output into a bounded, auditable, replayable unit of execution — with a receipt.

2System Architecture

2.1Structural Paradigm

Beagle is a modular monolith executing a directed acyclic graph. One Python process owns orchestration; work is fanned out to isolated sub-agent processes and pulled back into a single typed state object. It is not a microservice mesh — the container topology in §7.4 runs multiple copies of the same image with different entrypoints, not different services.

Three architectural properties define the system:

  • The DAG is the unit of governance. Acyclicity is enforced at load time, so an agent cannot loop indefinitely. Iteration counters and a circuit breaker in the routers bound retries independently core/graph.py:446,464.
  • Plugin seams, not hard-wired vendors. The sub-agent runtime is selected through a Python entry-point group (beagle.runtimes), with goose_cli as the default and http_agent for remote A2A execution. Outbound transports resolve through a second group (beagle.transports) and are auto-detected but never auto-activated.
  • Configuration is data, not code. A ~55-section dataclass schema is populated from a TOML config root; model identities are resolved through named role presets rather than literals, so retuning the model panel is a TOML edit config/schema.py:779.

2.4The Standard Research Graph

Every workflow reduces to a graph of typed phases. The built-in research graph is the reference shape and the fallback when a custom workflow cannot be loaded core/graph.py:548:

hydration → planning → execution ⇥ verification ⇥ synthesis → END where: ⇥ conditional edge, resolved by a router function hydration present iff (include_hydration ∧ HYDRATION_AVAILABLE) executor_router execution → {verification, synthesis, END} reviewer_router verification → {synthesis, END} error_router any failed node → retry target, bounded by (operational.total_iterations, operational.error_count)

Each phase binds to a named agent skill with its own timeout budget: research-planner (180 s), search-executor (180 s), fact-checker (300 s), and synthesis-writer (300 s, dynamically scaled by upstream fan-out) core/nodes.py:641–757. Synthesis is contractually required to emit both prose and a JSON findings block, which is what makes findings machine-persistable to the tracking database.

2.5Cross-Verification Collaboration Protocol

CVCP is a LangGraph subgraph that treats the primary agent's output as an untrusted claim protocols/cvcp.py. Two fact-checker agents run concurrently against the same execution context, each capped at half the verification budget so a slow attacker cannot starve its sibling. A single FAIL verdict fails the round.

A second, independent gate runs ground-truth validation over every file path the report cites, matched against a hallucination-pattern set that includes diff markers, temp paths, and known fabrication targets. Ground-truth failure takes priority over the adversarial verdict and always forces a retry. After max_cvcp_attempts (default 3) the run terminates and the surviving hallucinated citations are carried into the final report rather than silently dropped.

3.4Retrieval Tiers

Two index tiers coexist under the data root — instance_rag (per-project, the default) and main_rag (shared) — selected by BEAGLE_RAG_TIER and overridable wholesale by BEAGLE_KNOWLEDGE_DIR infrastructure/rag_paths.py. Ingestion parses source into AST entities, writes graph nodes and relations to Kùzu in bounded transactions, and streams embeddings into LanceDB in batches with periodic collection to hold resident memory flat. If the graph write fails, ingestion degrades to vector-only rather than aborting.

5Security and Access Control

The security model is fail-closed at every seam: transport, authentication, execution, and output. Defaults deny; capability is granted explicitly.

5.1Transport Enforcement

MCP servers accept stdio only by default — ALLOWED_TRANSPORTS is the frozen single-element set {"stdio"}. HTTP, SSE, and streamable-HTTP are blocked unless explicitly enabled and accompanied by valid bearer tokens infrastructure/mcp_security.py:54. There is no insecure fallback path.

http_transport_permitted ⟺ (transport ∈ HTTP_TRANSPORTS) ∧ mcp_auth.enabled ∧ (tokens ≠ ∅) ∧ (require_https ⇒ scheme = "https") where: HTTP_TRANSPORTS {http, sse, streamable-http} tokens mcp_auth.tokens, or $BEAGLE_MCP_TOKEN bind_address defaults to 127.0.0.1 (loopback) CORS allowed_origins defaults to ∅ — deny all, no wildcards

Token verification is constant-time, TTL-bounded, and supports rotation and revocation in place. Authentication failures are rate-limited to 10 per client per 300-second window, with the failure table capped at 10,000 entries so the rate limiter itself cannot be turned into a memory-exhaustion vector.

5.2Authentication and Authorisation

  • Sessions — JWT, HS256, with exp and iat both required claims and expiry verification on. A token missing either claim is rejected, which closes replay and cross-environment reuse auth/jwt.py:10.
  • Roles — three tenant-scoped roles: admin (all verbs), operator (get, post, execute), viewer (get). Casbin backs policy evaluation when installed; a hard-coded matrix is the fallback so authorisation never silently disappears with a missing dependency auth/rbac.py:17.
  • Tenancy — frozen Tenant records carry an enabled flag and a per-tenant default budget; Kùzu schemas are provisioned per tenant, giving isolation at the knowledge-graph layer as well as the policy layer.
  • Agent-to-agent — HMAC-signed tokens, optional Ed25519 agent-card signing via PyNaCl, and an OIDC verifier with JWKS retrieval and configurable clock skew. Strict mode (require_signatures) rejects unsigned messages outright.
  • Human-in-the-loop — a phase may declare require_approval. Execution halts unless approval_granted is set in state or --approve-all was passed core/graph_builder.py:418.

5.3Secret Management

Secrets are never baked into the image and never committed. A single loader replaces what were six duplicated implementations: environment variables are consulted first, then ~/.config/goose/secrets.yaml — which is rejected outright if its POSIX mode is more permissive than 0600. Values are cached for a TTL (default 300 s, disable with BEAGLE_SECRET_CACHE_TTL=0) so rotation is picked up without a restart, and are never logged secrets_loader.py.

Provider credentials in the model registry are referenced by environment-variable name only; an inline secret in providers.toml is not a supported shape. Outbound and inbound text passes a secret-scrubbing pass (scrub_secrets, scrub_output) before it reaches logs or reports.

5.4Input Validation and Output Vigil

  • Query gate — length-capped at 50,000 characters against token bombing, then passed through a semantic firewall combining pattern matching with an LLM-based safety evaluation.
  • Regex safety — google-re2 is a runtime dependency specifically so untrusted input is matched without catastrophic backtracking.
  • Code submission — an AST visitor validates submitted Python structurally, gating imports and dangerous constructs, rather than pattern-matching source text.
  • Path containment — workflow paths are resolved and checked with Path.relative_to against two anchors (workspace root, config root). A dangerous-character screen for .., ~, $, backtick, ;, |, &, and control characters runs before containment, so shell-metacharacter payloads are rejected independently of where they resolve core/workflow_loader.py:37.
  • Deserialization — LangChain load/loads are wrapped to force allowed_objects="core" and secrets_from_env=False, hardening against serialization-injection RCE and prompt-path traversal.
  • Banned constructs — the build gate hard-fails on yaml.load, unguarded pickle.load, datetime.utcnow(), truncated UUIDs, and wall-clock timestamps used for elapsed duration.

6Observability and Telemetry

6.1Logging

Logging is structlog over the standard library, emitting JSON when BEAGLE_LOG_JSON is set. Every record carries the active OpenTelemetry trace and span ID through a correlation processor, and a correlation-failure counter is exposed so silent loss of trace context is itself observable rather than invisible observability/logging.py:41. MCP tool invocations additionally carry a per-request correlation ID.

6.2Metrics and Tracing

The collector subscribes to the internal event bus and records token usage, operation duration, cost, node completion and failure, and workflow completion. Spans follow the OpenTelemetry GenAI semantic conventions, so model, token counts, and cost land on the span rather than only in logs observability/genai.py:68. Export is OTLP; a Prometheus HTTP exporter is available under the observability extra. A LangSmith bridge is available for teams already invested in that toolchain.

6.3Health and Self-Repair

A periodic collector (default 60 s) snapshots resident memory, file-descriptor pressure, thread count, zombie children, circuit-breaker states, rate-limiter saturation, cache hit rate, subprocess-pool failure rate, event-bus depth, and database statistics, reducing them to a single health score.

score ∈ [0,1] state := critical iff score < 0.3 | degraded iff score < 0.6 | healthy otherwise restart_permitted ⟺ (consecutive_critical ≥ 3) ∧ (now − last_restart ≥ 300 s) ∧ (restarts_so_far < 5) where: restart checkpoint state → drain subprocesses (≤10 s) → shut down subsystems (≤30 s) → re-exec thresholds rss_warn 1024 MB / critical 2048 MB; fd 80% / 95% of limit; threads 100 / 200

The container health check invokes python -m beagle.infrastructure.health_check, a purpose-built module that exercises the subsystems. A start_period of 60 s absorbs embedding-model load so a slow cold start is not misread as unhealthy and restarted in a loop.

6.5Cost Governance

Cost is a first-class runtime signal, not a post-hoc report. The tracker meters input and output tokens per call against per-model pricing, maintains context-window utilisation, and warns at 80 % of both the budget and the context window, escalating at 95 % context. A prompt may occupy at most 70 % of the context window, which reserves headroom for the completion cost_tracker.py:27. Budget defaults: 10.0 USD per workflow, warn at 0.8, hard system limit 50.0 USD.

# 2. Reproducible install straight from the lockfile (the SSOT)
uv sync --frozen --no-dev

# 3. Dev extras, non-editable, from the CPU torch index.
#    The CPU index matters: a default PyPI resolve pulls a multi-GB CUDA stack.
uv pip install ".[dev]" \
  --extra-index-url https://download.pytorch.org/whl/cpu --no-deps

# 4. Seed the config root at ~/.config/beagle
uv run beagle config init

# 5. Provide the provider credential
export OPENAI_API_KEY="..."

# 6. Gate before running anything
make check          # ruff + vulture + mypy (zero-error gate)
make banned         # forbidden-construct scan
make test           # full suite, 120s per-test timeout

# 7. Rehearse, then run
uv run beagle run research "What does the auth module do?" --dry-run
uv run beagle run research "What does the auth module do?" --budget 5.0

Index the target repository before expecting retrieval to answer anything about it — call the rag_ingest MCP tool, or drive it from the CLI. Until ingestion completes, hydration returns empty and agents fall back to unaided search.

7.4Production Deployment

The shippable artefact is a single multi-stage image built from the wheel. It contains no source tree and no credentials; all operator configuration is mounted at runtime.

# Build the wheel, then the image (Makefile derives the tag from pyproject)
make build
make image-build                         # docker/Dockerfile, python:3.13-slim

# Publish
make image-push REGISTRY=ghcr.io/<owner>

# Run standalone (loopback-published, hardened, resource-bounded)
export BEAGLE_MCP_TOKEN=$(openssl rand -hex 32)
make container-up                        # docker/docker-compose.yml
make container-down

# Or integrate the full MCP mesh into an existing Compose stack
DEV_STACK_DIR=/path/to/stack make dev-stack-integrate

The build sequence is deliberate and should not be reordered: the wheel is installed --no-deps first so the exact torch pin can be read back from its own metadata; that pin is then installed from the PyTorch CPU index before the full resolve, which makes it impossible for the resolver to substitute the multi-gigabyte CUDA build.

Exposure policy

Every MCP surface in the reference stack is internal-network only. beagle-rag fails closed without BEAGLE_MCP_TOKEN; openclaw is protected by network isolation alone until the plugin ships native HTTP authentication — do not add a host port publish for it. Host ports are bound to 127.0.0.1; put a reverse proxy in front of anything that needs LAN or internet reach.

7.5Daemon Mode

beagle daemon watches the workspace's git HEAD, computes a change set, matches it against trigger rules, and dispatches the corresponding workflow. Use it for continuous audit — a security workflow on every change to an auth path, for instance. Daemon lifecycle transitions are published to the event bus as first-class events, so daemon behaviour is observable through the same pipeline as workflow execution.

7.6Upgrade

# Build and install into the target venv.
# --no-deps is required: a default resolve pulls the GPU torch stack.
make build
uv pip install --reinstall --no-deps dist/beagle-*.whl
uv sync --frozen --no-dev --no-install-project

# Restart daemon and MCP servers so stale in-memory modules are dropped
# Then confirm the running version and subsystem health
beagle --version
beagle health
beagle doctor

Verify with beagle doctor before returning the system to service. The version-consistency CI gate asserts that the package __version__, pyproject.toml, the git tag, and the README badge all agree — a mismatch after upgrade indicates a partial install, not a cosmetic problem.

9Hazards and Known Limits

The following are properties of the system as built, not defects. Each carries an operational consequence worth knowing before deployment.

Table 9-A — Operational hazards
ConditionConsequenceMitigation
RAG index not builtHydration returns empty; agents plan without code grounding and cost rises without a corresponding quality gain.Run rag_ingest against the target repository before the first governed run. Check rag_status.
Kùzu buffer pool too small for the corpusIngest fails with an allocation error, or degrades to vector-only retrieval — graph traversals silently return nothing.Raise BEAGLE_KUZU_BUFFER_POOL_MB and BEAGLE_KUZU_MAX_DB_SIZE_MB. Ingest logs the degrade explicitly; do not treat it as benign.
goose binary unresolvedEvery sub-agent subprocess call fails and trips the circuit breaker; the workflow reports errors with no obvious cause.Set GOOSE_BIN explicitly. beagle doctor detects this.
Default PyPI resolve for torchPulls a multi-gigabyte CUDA stack onto a CPU-only host.Always install the wheel --no-deps, or pin the CPU index. The container build already does both.
MicroVM enabled on a host without KVMRuns refuse to start — by design, since allow_fallback is false.Provision Firecracker, the kernel image and the rootfs, or leave sandbox_microvm.enabled = false.
CVCP attempts exhaustedThe report is released with unresolved hallucinated citations attached rather than being withheld.Treat a run carrying hallucinated_files as requiring human review before its findings are actioned.
HTTP MCP without a tokenThe server refuses to boot — intentional fail-closed behaviour, not a crash.export BEAGLE_MCP_TOKEN=$(openssl rand -hex 32)

Method

Every factual claim in this manual was derived by direct reading of the source distribution at version 1.4.1. Structural counts are measurements taken against the working tree at issue date. Where a claim rests on a specific implementation detail, the source location is cited inline in monospace. Claims about runtime behaviour under load — throughput, latency at scale, retrieval precision — were not measured for this document and are not asserted anywhere in it.
